# 60fps motion research

60fps is a curated recording library of product and motion examples, not one reusable source-code package. Preserve the distinction between shots, apps, app sites, motion, snippets, glossary entries and supporting pages. Filters are discovery metadata, not additional unique animations.

The Storyboards landing page publicly advertises 67 breakdowns and exposes preview titles, while access to the full breakdowns requires Pro. Public headings are retained in the page index. The paid storyboard content, diagrams and detailed analysis were not accessed or reconstructed from their titles.

The public catalogue and media observations retain the original page, title, available source/media links, duration, resolution and sampled times. Site navigation or related shots can contribute additional media to the HTML; the survey uses the first primary video candidate and must not be treated as proof that every related clip was watched. No video collection is republished.

## Read a sequence as behavior

Record the visible starting state, apparent trigger, movement, overlapping phases, settled state and available reverse path. Identify what keeps visual continuity: the same card, text baseline, container outline, image crop, shared element or focus location. Distinguish direct finger tracking from released inertia, snap, spring settlement and decorative loops.

Use the site's gesture/effect/pattern/element categories to discover relevant references even if the user cannot recall an app or website name. Navigation, onboarding, loaders, timers, success states, charts, cards, menus, pickers and sheets are useful across domains; do not limit the collection to portfolio examples.

## Limits on precision

A recording can show that an element overshoots, fades, blurs, folds or springs. It does not disclose stiffness, damping, easing code, touch thresholds, interruptibility, device frame rate or real task outcomes. Measured clip timestamps are observations, not source constants. A title containing “spring” or “60fps” is not a performance benchmark.

Fonts and assets inside recordings need original provenance; the host page's computed font is unrelated. Exact source or downloadable snippet availability must be checked at the original entry. Login/Pro controls are access boundaries. Do not bypass them or publish creators' media as an asset pack.

The 32 public snippet pages contain 64 distinct code blocks after deduplicating repeated responsive markup. They are retained under ignored `.local/upstream/60fps-snippets`, with [parameter/hash records](catalogue/snippet-source.json) and [per-snippet guides](snippets/). Literal durations, delays, spring parameters and input/lifecycle locations come from source. They are principally SwiftUI examples: preserve platform semantics and reduced-motion handling instead of treating them as drop-in React components. Full snippet source is not republished because a blanket redistribution license was not established.

For each selected implementation, test keyboard/touch alternatives, reduced motion, focus, repeat/cancel paths, real async failure and application persistence. Preserve a pleasing animation's information and hierarchy while adapting it to the user's real task.
