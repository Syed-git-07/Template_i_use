# Choose a reference by the task

This library serves all domains and projects. Search it even when the user does not name a website. Named favorites are useful priorities; the full catalogues remain in scope.

| Need | Start here | Preserve |
| --- | --- | --- |
| Clean forms, alerts, dialogs, menus, tables, ordinary navigation | [shadcn/ui](shadcn/README.md) | Clear hierarchy, complete behavior, sensible density, focus and keyboard semantics; this is the user's minimum design baseline |
| Small feedback after an action, interruption and recovery | [Interior](interior/README.md), [Bencho](bencho/README.md) | Reserved dimensions, honest async states, cancellation, repeated-input behavior and reduced-motion information |
| Animated text, cards, menus, backgrounds and tactile controls | [React Bits](reactbits/README.md) | Exact selected source/variant, motion parameters, continuous input response, disposal and error paths |
| Composable text/layout/overlay motion | [Motion Primitives](motion-primitives/README.md) | Layout continuity, controlled state, transition configuration and accessibility supplied by the final composition |
| App/workspace, form, AI and richer component patterns | [Cult UI](cult/README.md) | Component dependencies, state ownership and real service integration |
| Expressive landing sections, spatial effects, shaders and microinteractions | [Aceternity](aceternity/README.md) | Original layering, pointer geometry, responsive/performance behavior and license/access limits |
| Visual discovery across typography, style and industry | [Viewport](viewport/README.md) | Creator attribution and the observed sequence; distinguish inspiration from available implementation |
| Mobile/product animation patterns, gestures and sequencing | [60fps](60fps/README.md) | Actual app context, trigger, intermediate states, reversal and timing evidence from recordings |

Minimal interfaces should still feel finished: consistent spacing, readable labels, deliberate focus states, clear validation and complete action feedback. “Use shadcn” is a baseline preference, not authorization to replace a project's existing stack or add every package blindly.

Use stronger motion when it helps orientation, explains a state change, supports direct manipulation or is explicitly requested. Avoid decorative repetition, filler UI narration and unnecessary helper paragraphs. Typography and visual structure matter as much as animation. Backgrounds are available for reference but no portfolio background has been selected.

The Viewport envelope contact form is a specific portfolio priority. Its [observed sequence](viewport/INTERACTIONS.md) is separate from the implementation plan and real email-delivery requirements.
